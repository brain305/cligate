# CliGate

> 되돌릴 수 없는 터미널 명령을, 실행하기 전에 멈춰 세우는 대화형 셸

2026 캡스톤디자인 · 1인 개발 · Python

## 문제

서버에서 `rm -rf`나 `git push --force`는 실행 직전까지 무엇이 사라지는지 알려주지 않습니다.
로컬 컴퓨터와 달리 서버에는 휴지통도 백업도 없어서, 한 번의 실수가 그대로 영구 손실이 됩니다.
그리고 ssh로 서버에 들어가는 순간은 대개 급할 때 — 배포나 장애 대응 중 — 라서 실수가 가장 잦은 순간이기도 합니다.

## 데모

**동작 시각화:** https://claude.ai/artifact/DCdcEaPgrq86FK64MXn2NF

```
cligate > git push --force

  ⚠ 강제 푸시 — 원격 커밋이 삭제됩니다

    8cfd49d  test: 인증 테스트 추가      29초 전
    9369a0b  fix: 로그인 리다이렉트 수정   29초 전

    권장  git push --force-with-lease

  진행하려면 force 입력: _
```

경고 문구 대신 **사라질 것을 이름으로 보여줍니다.** 그리고 `y` 대신 단어를 치게 해서 반사적인 엔터를 막습니다.

## 동작 원리

CliGate는 셸이 아니라 **셸 앞에 서는 입력 창**입니다. 입력 줄을 직접 받기 때문에,
셸이 글롭(`*.log`)이나 변수(`$DIR`)를 전개하기 **전**의 원본을 볼 수 있습니다.

```
입력 → 파싱 → 위험 판정 → 게이트 → 셸에 위임
               │              │
               │              └─ 위험하면 확인을 묻고, 취소하면 실행하지 않는다
               └─ 명령어가 아니라 "명령어 + 현재 상태" 로 판정한다
```

같은 `rm *.log`라도 git에 커밋된 파일만 지우면 복구할 수 있지만,
커밋 안 된 파일이 섞여 있으면 영구 손실입니다. **등급은 명령어가 아니라 명령어와 상태의 쌍에서 나옵니다.**

## 구조

| 파일 | 역할 |
| --- | --- |
| `cli.py` | 진입점. 입력 루프 |
| `parse.py` | 명령 분리(`&&`, `\|`, `;`), 문법 검사 |
| `builtin.py` | `cd`, `exit`, `export`, `unset` — 셸에 넘기면 상태가 안 남는 명령들 |
| `gate.py` | 위험 명령 판별 |

## 진행 현황

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | 설치 배선, `cligate` 명령어 | ✅ |

## 진입형과 래퍼식

CliGate는 두 가지 방식으로 쓸 수 있도록 설계했습니다. 지금은 **진입형**을 먼저 만들고 있습니다.

```
진입형:  cligate                 → 들어가서 한 줄씩 입력 ─┐
                                                         ├→ 파싱 → 판정 → 게이트 → 실행
래퍼식:  cligate git push --force → 명령 앞에 붙여서 실행 ─┘
```

두 방식은 **입구만 다르고 안쪽은 같습니다.** 한 줄을 처리하는 과정(파싱 → 판정 → 게이트 → 실행)을
하나의 함수로 분리해두었기 때문에, 래퍼식은 나중에 입구만 추가하면 됩니다.


| | 진입형 | 래퍼식 |
| --- | --- | --- |
| 자동완성 | ✅ | ❌ 이미 엔터를 친 뒤 |
| `*.log` 원본 보기 | ✅ | ❌ 셸이 이미 파일 목록으로 전개함 |
| 빈 변수 `$DIR` 탐지 | ✅ | ❌ 이미 빈 문자열로 사라짐 |
| 스크립트 안에서 사용 | ❌ | ✅ |


### 향후 과제

- **래퍼식 모드** — `cligate git push --force` 처럼 명령 앞에 붙여 쓰는 방식.
  진입형과 같은 판정 엔진을 공유하므로 입구만 추가하면 된다.
  스크립트 안에서도 쓸 수 있지만, 셸이 먼저 전개한 뒤에 받기 때문에
  자동완성과 글롭·빈 변수 탐지는 불가능하다.
